Architectural Study: Direct Merchant UPI QR Code & Online Payments Engine
A comprehensive deep-dive into zero-commission payment processing, NPCI deep-linking, dynamic vector QR generation, and real-time reconciliation for multi-tenant local commerce.

1. Executive Summary & Strategic Rationale

ZYVEN is an infrastructure SaaS platform enabling local independent businesses (grocers, apparel stores, bakeries, electronics vendors) to launch their own branded online storefronts (zyven.me/[store-slug]) for in-store pickup (BOPIS).

A critical architectural decision in ZYVEN was not using conventional third-party intermediary payment gateways (e.g. Razorpay, Stripe, Cashfree) as the sole payment highway, but rather engineering a Direct Peer-to-Merchant (P2M) Unified Payments Interface (UPI) QR Code Engine.

Strategic Advantage: Why Direct UPI Beats Traditional Gateways
  • 0% Merchant Discount Rate (MDR): Standard gateways take 2.0% – 3.0% + GST on every retail transaction. On low-margin items like flour, rice, milk, or electronics, 2.5% wipes out 30% to 50% of a neighborhood shopkeeper's net profit.
  • Instant T+0 Settlement (0 Seconds): Gateways hold merchant funds for T+2 or T+3 business days. With direct UPI, payments credit straight from the customer's bank account into the shopkeeper's account immediately.
  • No Complex KYC Gateways: Shopkeepers already possess an operational UPI VPA (Google Pay, PhonePe, Paytm QR). ZYVEN leverages their existing banking handle instantly.

3. NPCI UPI URI Specification & Deep-Linking Protocol

The National Payments Corporation of India (NPCI) defines an open URI protocol specification (upi://pay) supported by all mobile operating systems (iOS and Android) and banking apps. When a mobile browser triggers this URI, the operating system's application intent dispatcher prompts the customer to choose any installed UPI application.

Standard NPCI Protocol Syntax

upi://pay?pa={VPA}&pn={PAYEE_NAME}&am={AMOUNT}&cu=INR&tn={TRANSACTION_NOTE}

Parameter Breakdown & Validation Rules

Parameter Full Name ZYVEN Encoding Rule Description & Example
pa Payee Address Sanitized string, lowercase Virtual Payment Address (VPA) of the store (e.g., sharmagrocery@upi).
pn Payee Name URL-encoded UTF-8 Business trade name displayed in banking app (e.g., Sharma%20Grocery%20Store).
am Amount Fixed 2-decimal float Exact payable total (e.g., 499.00). Prevents user from entering wrong amounts.
cu Currency Fixed INR Indian Rupee ISO 4217 currency code.
tn Transaction Note URL-encoded reference Attached reference (e.g., Order%20%23ZYV-20261030-1011). Printed in customer's bank passbook.

4. Core Code Implementation: The UPI Engine (src/lib/upi.ts)

The engine consists of two core functions: buildUpiUri() for deep link generation and generateQrDataUrl() for dynamic vector/raster QR encoding. 

import QRCode from 'qrcode';

export interface UpiPaymentDetails {
  upiId: string;
  payeeName: string;
  amount?: number;
  transactionNote?: string;
  referenceId?: string;
}

/**
 * Builds the standard NPCI Unified Payments Interface (UPI) deep link URI
 * Output: upi://pay?pa={upiId}&pn={payeeName}&am={amount}&cu=INR&tn={transactionNote}
 */
export function buildUpiUri({
  upiId,
  payeeName,
  amount,
  transactionNote,
}: UpiPaymentDetails): string {
  const cleanUpi = upiId.trim();
  const cleanName = encodeURIComponent(payeeName.trim());
  let uri = `upi://pay?pa=${cleanUpi}&pn=${cleanName}&cu=INR`;

  if (amount !== undefined && amount > 0) {
    uri += `&am=${amount.toFixed(2)}`;
  }

  if (transactionNote) {
    uri += `&tn=${encodeURIComponent(transactionNote.trim())}`;
  }

  return uri;
}

/**
 * Generates an optimized QR Code SVG or Base64 Data URL for high-contrast mobile scanning
 */
export async function generateQrDataUrl(
  text: string,
  options?: { width?: number; margin?: number }
): Promise {
  const width = options?.width || 280;
  const margin = options?.margin || 1;

  return QRCode.toDataURL(text, {
    width,
    margin,
    color: {
      dark: '#09090b', // Zinc-950 deep contrast for fast phone camera acquisition
      light: '#ffffff',
    },
    errorCorrectionLevel: 'M', // 15% Error Correction Recovery
  });
}

5. Complete End-to-End Payment Sequence

The interaction flow between the Customer, Storefront, PostgreSQL Engine, and NPCI Payment App operates in a strict multi-stage lifecycle:

1
Checkout Selection
Customer selects UPI_ONLINE or PAY_AT_STORE.
→
2
Atomic Stock Lock
PostgreSQL row lock reserves stock & generates Order ID.
→
3
Dynamic QR & Intent
QR rendered with merchant VPA and locked amount.
→
4
Bank Authorization
Customer enters 4/6-digit UPI PIN in GPay/PhonePe.
→
5
Settlement & UTR
Money credited to merchant; UTR recorded for audit.

Step-by-Step Execution Lifecycle

  1. Atomic Order Initiation (/api/checkout): Customer submits their cart. The server executes a PostgreSQL transaction using SELECT ... FOR UPDATE on the business inventory records. Physical stock is guarded, and quantityReserved increments to prevent overselling.
  2. Order Record Persistence: An Order record is persisted with paymentMethod: 'UPI_ONLINE' and paymentStatus: 'PENDING'. The order number (e.g. ZYV-20261030-1011) is issued.
  3. Redirection to Real-Time Tracker (/[slug]/orders/[orderNumber]): The customer is redirected to the live order tracker. The page instantiates the UpiPaymentCard component.
  4. Dynamic Client Handshake:
    • On Mobile Device: The customer taps "Pay with any UPI App". The browser invokes upi://pay?..., launching Google Pay, PhonePe, or Paytm with the payee and amount pre-filled and non-editable.
    • On Desktop Browser: The customer scans the high-contrast on-screen QR Code using their phone's camera or UPI scanner.
  5. Audit Logging & Bank Reference (UTR): The customer can paste their 12-digit bank UTR reference into the timeline. When the merchant confirms the incoming payment alert, they transition the order to ACCEPTED with one click.

8. Security, Reconciliation & Fraud Prevention

The Trust Boundary in Zero-Commission P2M UPI

In third-party aggregator setups (e.g. Razorpay), the aggregator verifies the webhook signature before releasing the order. However, raw peer-to-merchant UPI VPAs have no third-party intermediary, which eliminates all transaction fees. ZYVEN balances this through a robust 3-point reconciliation protocol:

  • 1. Frozen Amount in Deep Link: The am parameter is cryptographically included in the QR string. The customer cannot tamper with the amount in their payment app.
  • 2. Customer 12-Digit Bank UTR Capture: When a customer pays, their bank generates a 12-digit Unique Transaction Reference (UTR). Customers can enter this reference in ZYVEN's order tracking screen. This is saved to order.upiTransactionRef and logged in OrderStatusHistory.
  • 3. Merchant 1-Tap Counter Verification: When the customer arrives for physical pickup, the merchant verifies the ₹ credit SMS / notification on their phone or compares the UTR, then taps "Mark as Paid" in their dashboard. Since BOPIS requires physical store pickup, goods never leave the store until payment is verified.
